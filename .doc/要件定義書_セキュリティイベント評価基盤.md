1. はじめに
1.1 背景

近年、認証・認可および業務操作における不正行為が高度化しており、
従来の静的ルールベースのみでは十分なリスク判断が困難となっている。

本要件定義書では、
SecurityEvent を入力とし、統一されたリスク評価結果を返却する基盤
（以下「本システム」）の要件を定義する。

1.2 目的

認証・業務操作に対するリスクを定量的に評価する

ルールベース + AI（LLM）による柔軟な判断を可能にする

システム間で共通利用可能な評価 I/F を提供する

2. 用語定義
用語	説明
SecurityEvent	セキュリティ判断対象となるイベント
RiskDecision	リスク評価結果
LLM	大規模言語モデル
Signal	リスク判断に使用される指標
3. 対象範囲
3.1 対象

認証処理（ログイン、トークン発行 等）

業務処理（重要操作、設定変更 等）

3.2 非対象

UI / フロントエンド実装

実際のブロック処理（判断のみを行う）

4. 機能要件
4.1 セキュリティイベント受付

本システムは以下の情報を受信する。

必須項目
項目	  型	     説明
eventId	string	イベント識別子
action	string	auth / business
actor	object	行為主体
context	object	リクエスト文脈
resource	object	操作対象
signals	object	リスク指標
任意項目
項目	 型	     説明
payload	object	脱敏済み業務データ
history	object	関連過去イベント
4.2 リスク評価

ルールベース評価を優先的に実行

必要に応じて LLM による補助評価を実施

評価結果は RiskDecision として返却する

4.3 フォールバックルール

以下の場合はデフォルト判断を行う。

条件	設定値
情報不足	riskLevel = MEDIUM
	suggestedAction = CHALLENGE
	confidence ≤ 0.5
	signal = insufficient_context
5. 非機能要件
5.1 セキュリティ

payload は必ず脱敏済みであること

個人情報を含まないこと

5.2 信頼性

同一入力に対して同一結果を返却する

6. 制約事項

System Prompt は読み取り専用とする

Runtime Prompt は変更可能とする
