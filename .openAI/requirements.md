Real-Estate Authorization System

（ドラフト / 承認待ち）

1. 概要（Introduction）

本ドキュメントは、不動産管理プラットフォーム（real-estate）における
認証および認可（Authorization）機能の要件を定義するものである。

本機能の目的は、
ユーザーの役割に応じて安全かつ適切に API へのアクセスを制御し、
権限昇格や不正操作を防止することである。

⚠ 本要件はドラフトであり、
最終決定は人間による承認をもって確定する。

2. スコープ（In Scope / Out of Scope）
2.1 In Scope

ユーザー認証（メール＋パスワード）

4. 機能要件（Functional Requirements）
FR-01 ユーザー認証（ログイン）

ユーザーストーリー
As a ユーザー, I want to ログインできるようにしたい, so that 自分の権限に基づく操作ができる。

受入条件（EARS）

WHEN 正しいメールアドレスとパスワードが入力された場合
THEN システムは認証を成功させなければならない

WHEN 認証に成功した場合
THEN システムは有効期限付き JWT を発行しなければならない

WHEN 認証に失敗した場合
THEN システムは具体的な内部理由を返してはならない

FR-02 パスワード管理

ユーザーストーリー
As a システム管理者, I want パスワードを安全に管理したい, so that 情報漏洩リスクを低減できる。

受入条件（EARS）

WHERE パスワードが保存される場合
THEN 平文で保存してはならない

WHERE パスワード検証を行う場合
THEN ハッシュ化された値と比較しなければならない

FR-03 ロールベース認可（RBAC）

ユーザーストーリー
As a システム, I want ユーザーのロールに応じて API を制御したい, so that 不正操作を防止できる。

受入条件（EARS）

WHEN API が呼び出された場合
THEN システムはユーザーのロールを確認しなければならない

WHEN ロールが許可されていない場合
THEN システムはアクセスを拒否しなければならない

WHEN Pending_Agent が保護 API を呼び出した場合
THEN システムは拒否しなければならない

FR-04 JWT の有効期限管理

ユーザーストーリー
As a セキュリティ担当, I want トークンの有効期限を管理したい, so that 長期不正利用を防げる。

受入条件（EARS）

WHEN JWT の有効期限が切れている場合
THEN システムは認証失敗として扱わなければならない

WHEN JWT が改ざんされている場合
THEN システムは拒否しなければならない

5. 非機能要件（Non-Functional Requirements）
NFR-01 セキュリティ

JWT 秘密鍵は設定ファイルまたは環境変数で管理すること

権限昇格が可能な API は特に厳格にチェックすること

NFR-02 エラーハンドリング

認証・認可エラーは一貫した形式で返却すること

内部実装の詳細をエラーに含めないこと

6. エッジケース・考慮事項

ロールが未設定のユーザーの扱い

削除済みユーザーのトークン再利用
